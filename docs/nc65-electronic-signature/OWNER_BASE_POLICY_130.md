## 升级脚本

脚本仅用于已核实的 QDNC 测试环境，调用前应检查连接的数据库、服务端和模式。脚本包含 Oracle DDL，不能将 DDL 当成可由同一事务整体回滚的操作。

1. 保留数据库配置、当前 NC Home 补丁及功能节点参数备份，停止新请求，等待所有执行中请求结束，并记录所有集团和业务单元总控及按钮开关。
2. 运行 [01_precheck.sql](../../sql/nc65-electronic-signature/owner-base-policy/01_precheck.sql)，核对环境、版本、待处理请求、现有策略和相关业务字段。不得在仍有运行中请求时继续。
   物料节点与页签登记情况可通过 [05_material_readonly_precheck.sql](../../sql/nc65-electronic-signature/owner-base-policy/05_material_readonly_precheck.sql) 只读核对；空的独立按钮登记结果须结合原生页签和权限服务判断，不能直接当作已接入。
3. 离线构建和候选包校验通过后，在维护窗口执行 [02_schema.sql](../../sql/nc65-electronic-signature/owner-base-policy/02_schema.sql)。脚本逐表增列，包含已存在的历史表。若中断，先检查已完成的 DDL，再按检查结果恢复。Oracle DDL 隐式提交。
4. 关闭自动提交，在同一事务执行 [03_migrate.sql](../../sql/nc65-electronic-signature/owner-base-policy/03_migrate.sql)、[06_material_owner_routes.sql](../../sql/nc65-electronic-signature/owner-base-policy/06_material_owner_routes.sql) 和 [07_material_assignment_route.sql](../../sql/nc65-electronic-signature/owner-base-policy/07_material_assignment_route.sql)。检查旧授权、策略数量、实际节点、按钮及别名后显式提交。脚本沿用原有总控和集团按钮开关，新业务单元基础档案按钮默认关闭。
5. 在服务停止期间安装同一构建产物的客户端、公共层和服务端文件，核对散列和功能节点配置，再恢复暂停的后台任务。
6. 由现场负责人恢复中间件并重新登录。仅在验收样本组织配置所需按钮开关。

## QDNC 首批验收

选择已隔离的测试集团、业务单元 A 和 B、具备相应原生权限的账号，以及分别由集团和 A 创建并已分配给 B 的物料。测试前核实环境内的触发器、外发任务及业务影响；`990` 以现场主键和授权为准，不假定所有组织均已隔离。

| 用例 | 必须核对 |
|---|---|
| 集团所属物料、集团审计关/开 | 分别在集团和 B 修改，使用集团策略；集团审计关闭不产生业务审计，开启则产生。B 自身配置不改变结果。 |
| A 所属物料、A 审计关/开 | 分别在 A 和 B 修改，使用 A 策略；A 关闭不产生业务审计，开启则产生。B 自身配置不改变结果。 |
| 签名、事由和审计 | 覆盖三个独立开关的八种组合。仅事由必填时，只填写事由，不要求密码，不产生签名成功日志；必要时确认服务端拒绝空事由。 |
| 操作组织与查询条件 | 登录默认组织与查询选择的 B 不同；核对日志操作组织为 B，策略组织为物料主档所属组织。无唯一业务单元时检查明确提示。 |
| 所属组织改变 | 如果原生服务允许变更，核对变更本身按变更前组织策略，保存后下一次操作按新组织策略；不允许时核对原生错误。 |
| 页签、快照与权限 | 分别通过财务、采购真实页签保存，核对父物料归属、目标组织、原生页签权限、完整前后快照和物理字段。 |
| 旧授权失效 | 准备或签名后修改所属组织、所属组织总控或按钮策略，执行必须拒绝并要求重新发起。 |
| 混合归属批量 | 在同一业务单元列表选择集团所属和业务单元所属物料，同时选择两个目标业务单元。确认一次身份，按各物料所属组织分别决定审计。核对操作组织、策略所属组织、目标组织三列。 |
| 分配部分成功和故障 | 使用一个可分配目标、一个已存在关系的目标，再用一个可重复触发原生校验失败的目标单独复测。核对每个组合的结果。对隔离样本注入审计写入错误，检查该组合的 `bd_marorg` 和适用页签均回滚，其他已成功目标仍存在。 |
| 分配结果中断与归档 | 在隔离环境模拟客户端连接中断，按原请求号查逐目标结果。重查只能读取已有状态。确认存在待核对组合时批次不会归档。归档后检查部分成功结果以及已分配目标仍可恢复。 |
| 审计、日志授权 | 按请求号核对业务、签名、差异和全字段快照；按实际操作范围分别验证集团和业务单元列表、明细、导出和归档。旧日志所属组织显示“未记录”。 |

每个实际用例记录操作者、集团、操作组织、所属组织、目标组织、节点和按钮、请求号、策略版本、数据库前后行及事务结论。对于集团新增物料，核对自动生成的 `bd_materialconvert` 与 `bd_material` 在同一请求审计中按表和行展示。

分配用 [08_material_assignment_receipt.sql](../../sql/nc65-electronic-signature/owner-base-policy/08_material_assignment_receipt.sql) 按请求号核对在线结果。签名成功的组合由所属组织签名开关决定，实际提交且自身开启审计的组合才产生成功审计。已分配和回滚的组合不应有成功审计。逐表打开 `bd_marorg` 和适用页签的物理行快照，并与数据库同主键的全部列核对。

## 回退

先停新请求、排空并备份现有配置和证据，再关闭自动提交执行 [04_prepare_rollback.sql](../../sql/nc65-electronic-signature/owner-base-policy/04_prepare_rollback.sql)。核对集团基础档案总控关闭、1.3 新入口已退回，再显式提交。脚本保留新旧策略、逐目标结果、对象和审计证据，并取消未执行的 1.3.0 请求。完成后恢复经核实的 1.2.0 程序和对应客户端文件。重新开启集团总控前，先核对 1.2 的集团策略影响范围。

1.2 归档程序不认识新增归属字段，直接归档 1.3 在线记录会丢失这些字段。升级脚本预置四个回退保护触发器，回退标记生效时阻止旧程序删除带归属信息的在线请求及日志；回退脚本会检查保护已启用。回退期间暂停旧归档任务，1.2 页面不能展示新增归属字段，记录保留在数据库中。恢复支持这些字段的版本前不得解除保护；升级、回退和误触发归档的事务回滚均须在隔离环境实测。回退后还应核验业务单元总控、旧策略、历史日志和功能节点配置。
