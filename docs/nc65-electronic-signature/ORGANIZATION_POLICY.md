# 电子签名策略按业务单元管理

本文记录 1.1.0 的业务单元策略。升级 1.2.0 后，基础档案 77 项改由集团策略维护，业务单元策略页显示其余 166 项。见 [基础档案集团策略与验收](GROUP_BASE_POLICY_ACCEPTANCE.md)。

## 使用

在 NC Java 客户端打开「企业建模平台 → 电子签名管理（新版）→ 电子签名策略」。页签顶部提供业务单元参照、查询、组织总控及两个保存按钮。组织参照沿用 NC 标准业务单元的树、档案和搜索，单选后点「查询」。策略服务按所选业务单元校验 `QD_ES_POLICY / QUERY`。切换组织时清除上一组织的结果。

策略表包含正式清单的 243 项操作，显示功能节点、按钮、编码和接入状态。已接入行显示实际编码。其余行显示现场注册清单中已核实的编码，悬停可查看配对的节点、按钮和已定位的子页入口。待验证行只读。具备所选业务单元 `SAVE` 权限时，可在已验证行配置签名、事由必填和审计，再点「保存策略」一次提交修改。事由必填在签名生效时执行，首次配置默认为关闭。

状态显示使用客户端随包的 `operation-codes.xml`，不会自动读取后来新增的功能注册核对结果。2026-11-11 已在工作区补齐 48 条已核实的页签按钮编码，保留其“已登记，待接入”语义和只读保护；该目录更新尚未部署，实际客户端显示以安装版本为准。其余同名删除和定制操作仍需确认，见 [功能注册页签按钮核对](PAGE_REGISTRATION_20261110.md) 及 [待核对按钮](UNMATCHED_BUTTONS_20261110.md)。

组织总控独立保存，需要所选业务单元的 `MASTER` 权限。关闭组织总控后，该业务单元的签名和审计暂停生效，按钮配置仍可保存。独立的登录与安全事件照常记录。总控改变时推进组织版本，旧待执行授权失效。遇到版本冲突需重新查询。切换业务单元、重新查询或关闭页签时会确认是否放弃未保存的修改。

## 从 QDNC 1.0.0 升级

脚本位于 `sql/nc65-electronic-signature/organization-policy/`。在已确认的共享测试维护窗口操作，并按环境实施记录保留原应用文件、业务单元策略、总控、请求及日志备份。

1. 排空用户操作及本项目后台任务，停止 NC 中间件并关闭客户端。先运行 `01_precheck.sql`，核对目标为 QDNC、存在 `1.0.0`、无 `RUNNING` 请求、无无效的旧生效策略。记录脚本预计迁移的组织及版本。
2. 确认后，以 QDNC 用户执行一次 `02_create_org_control.sql`。Oracle 的建表会隐式提交，使用独立会话执行。若已存在该表，按脚本核对联合主键、列和约束后再继续。
3. 关闭自动提交，使用支持 Oracle PL/SQL 脚本的客户端执行 `03_migrate_org_control.sql`。确认已写入 `1.1.0` 标记，回显的组织及版本与预检一致后提交。核对失败时回滚本次数据事务。迁移保留现有按钮策略。只有旧集团总控开启且已有启用的签名或审计策略的组织继承开启。已有策略或在线请求的组织版本高于旧集团版本和本组织的旧请求版本，其余组织缺省关闭。
4. 同一维护窗口安装同一候选包内的三个 `uapbd` JAR 并核对发布清单哈希。应用启动前确认版本和表结构。重启中间件，重新启动 NC Java 客户端并登录，使用现有四个菜单和权限。安装与备份方式见 [环境实施记录](ENVIRONMENT_EXECUTION.md#操作顺序)。

| 用途 | 相对 NC HOME 的路径 |
|---|---|
| 公共 RPC 接口及 DTO | `modules/uapbd/lib/qd_esign_uapbd_public.jar` |
| 服务端策略与执行依赖 | `modules/uapbd/META-INF/lib/qd_esign_uapbd_private.jar` |
| Java 客户端策略窗口 | `modules/uapbd/client/lib/qd_esign_uapbd_client.jar` |

## 撤回至 1.0.0

在维护窗口排空执行中请求、关闭客户端和中间件、暂停相关任务并保全现有配置及签名、审计证据。关闭自动提交后执行 `04_prepare_legacy_rollback.sql`。核对 `1.1.0-RB` 标记与旧集团开关均关闭后提交，再从同一备份恢复三个旧版 JAR，启动原版本。

撤回脚本会推进旧集团版本至该集团各组织版本及在线请求版本之上，保留组织总控表、按钮配置和日志。以后重新升级需要审核新的切换脚本及现有配置，原迁移脚本会识别撤回标记。

## QDNC 现场验收

| 用例 | 核对结果 |
|---|---|
| `yonyou02` 进入并选择 `990` 后查询 | 同一账号对照 NC 标准业务单元参照，核对组织树、搜索、编码、名称和单选。当前清单应返回 243 行。选择 NC 可见但无策略查询权的组织时，服务端拒绝查询，页面提示并清除上一组织结果。 |
| 按组织授权 | 用具备维护权限的账号在已验证行更改选项并批量保存。分别用只有 `QUERY`、`SAVE`、`MASTER` 对应组合权限的账号核对服务端拒绝越权组织和越权操作。 |
| 未保存修改 | 分别修改按钮和组织总控，测试切换、重新查询和关闭时的提示。取消后仍在原业务单元，确认放弃后清除原修改。分别保存策略和总控时，另一部分的未保存修改仍保留。 |
| 并发批量保存 | 两个授权客户端读取同一组织版本。在另一端改动其中一行后，提交包含该行和一条未冲突行的批次。应提示重新查询，未冲突行也保持原版本。另在隔离会话中于批次写入阶段注入冲突，验证 CMT 撤销此前已写入的行。 |
| 组织隔离 | 在两个获准且隔离外发的业务单元使用已接入动作，保存不同的行配置和总控，分别核对实际业务的请求、签名和审计。关闭一个组织的总控应只暂停该组织，且其行配置仍可编辑。 |
| 四种签名和审计组合 | 总控开启后逐个验证都关闭、仅签名、仅审计、同时启用。分别勾选和取消事由必填，检查签名交互和实际审计结果。 |
| 旧授权失效 | 留下一条未确认签名请求及一条已确认未执行请求，再关闭并重新开启该组织总控。原密码确认或执行业务请求应被拒绝，同一按钮新请求按最新配置执行。另一组织的既有授权继续使用其自身版本。 |

物料 `10140MAO / Save / INSERT` 的接线和试点授权见 [物料试点](MATERIAL_SAVE_PILOT.md)。只读菜单验收时保持各组织总控关闭。记录实际账号、业务单元、请求号和结论，并与离线报告分开。

## 验证记录

离线使用 NC Home 自带 IBM JDK 7 编译，新增测试覆盖 243 行加载、未验证行只读、权限标志、组织隔离、行版本冲突、冲突向 CMT 传播和总控版本失效。结构契约检查核对 18 张核心表与 17 项 Java 映射。内存数据验证了迁移开关继承、迁移前旧请求版本和撤回前新请求版本的推进规则。原生主题组件在无登录会话的测试进程报告缺少 NC URL，离线断言通过。

2026-11-09，QDNC 只读预检确认目标匹配，`1.0.0` 存在，`1.1.0` 及撤回标记未安装。组织总控表尚未创建，旧总控、按钮策略和在线请求均为零条。无执行中请求或无效的旧生效策略。组织 `990` 是当前试点集团的有效业务单元，目录与策略关联查询返回 243 条 `UNMAPPED / N`、零条已配置策略。DBX 拒绝预检中的 CTE 预览，已用三张源表计数独立核实本环境无待迁移组织。

2026-11-09 11:24，使用 NC 原生凭据解码和 Oracle JDBC 直连 QDNC，依次执行 `01_precheck.sql`、`02_create_org_control.sql` 和 `03_migrate_org_control.sql`。迁移回显核对后提交，新会话确认 `1.1.0` 标记、组织总控表的联合主键及开关和版本约束均有效。组织总控、按钮策略、在线请求各为零条，目录 243 项。执行记录位于 `build/deployment/qdnc-org-policy-20261109-111940-ba84d20a/execution-native.log`。
