# 库存联调证据台账

`inventory-acceptance-evidence.csv` 按正式范围矩阵的 83 个 `scopeId` 各列出 10 类用例，共 830 条；建立时全部为 `NOT_RUN`，不代表发生过 NC 操作。四种签名／审计开关组合分别记录，另列取消、错密、越权、重复提交、批量部分成功和审计写入失败回滚。现场还应针对每个动作记录自身的状态、库存和源单／生成单验证，不能仅以通用用例代替。

执行后按行填写集团、业务单元、操作人、带时区执行时间、实际结果和证据位置；业务成功的四种开关组合还要填写真实对象主键和单号。多个请求号、主键或单号使用分号分隔。签名／审计证据引用可定位的请求号和日志记录；无生成单时，在生成单证据中注明核对依据。证据文件不得保存密码、令牌或密钥。

状态使用 `NOT_RUN`、`PASS`、`FAIL` 或 `NOT_APPLICABLE`。仅原生动作不支持批量时，可在批量用例标记 `NOT_APPLICABLE`，并写明原因和证明。失败保留实际结果和定位证据；修复后应保留失败资料，再以复测证据更新记录。每一行表示一个范围和用例类别，若有多次运行或多个对象，应在证据位置引用明细记录。

在项目根目录运行以下命令检查 83 个范围与用例覆盖、重复、状态及关键证据字段。脚本不连接 NC 或数据库；它只检查记录结构，不能证明截图、日志、事务回滚或业务结果真实正确。即使字段完整，也必须由业务和技术人员核验现场证据。

```powershell
pwsh -NoProfile -File tools/inventory-acceptance.ps1 -Mode Check
```

检查退出码为 `0` 表示必填字段齐备且没有未执行或失败项，`1` 表示记录结构或必填项错误，`2` 表示仍有未执行或失败项。脚本的 `Prepare` 模式可使用 `-File` 为新一轮生成空台账，遇到同名文件会拒绝覆盖；不要用新台账覆盖既有证据。
