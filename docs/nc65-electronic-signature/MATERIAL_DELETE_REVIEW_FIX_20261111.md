# 物料主档删除与图片清理审核修复

## 当前状态

源码和脚本仍是候选，**图片自动清理尚未完成，不能启用或部署为已验收功能**。后台对已登记任务只核验目录及物料状态，然后转为 `NEEDS_REVIEW`；不会调用原生递归删除，也不会以数据库路径消失冒充物理文件删除成功。文件节点清单与任务随物料删除、业务审计在同一事务登记；如果目录探测失败，则保留待核对任务。

物料批量删除使用一次策略准备与签名，按已授权物料逐项进入独立事务，记录成功、失败和结果未知。服务端按数据库主档取得版本来源、最新标记和所属组织，并按原生顺序加锁。审计包括已识别组织页签、子表及同源版本的实际前后行。对未知动态页签、未验证扩展配置或跨所属组织的同源版本，当前会拒绝执行。

本次没有向 QDNC 执行 DDL、DML，也没有部署到 NC Home；下述事务和结果均为源码设计，尚未经过真实 NC 客户端及原生服务验收。

## QDNC 只读取证（2026-11-11）

- 直接 JDBC 只读连接 QDNC，确认清理任务表尚不存在，物料主档删除集团路由仍为 `UNMAPPED/N`；本次未执行数据库 DDL 或 DML。
- `bd_assign_tab` 有九种物料组织服务，除财务、采购、销售、库存、计划、生产、成本和 `pfc` 外，还包含利润中心成本域 `pfcc`。其主表 `bd_materialpfcc` 主键为 `pk_mateprofcost`，子表 `bd_materialpfccsub` 主键为 `pk_mateprofcost_b`，以 `pk_mateprofcost` 关联。
- `sm_pub_filesystem.filepath` 和 `pk_doc` 的现场长度均为 `VARCHAR2(2000)`；物料图片路径下查询到 `isfolder=n,isdoc=z` 的文件节点。原生 `FileTypeConst` 将 `z` 识别为 NC65 文件存储；必须按实际文件存储实现核实，不能只检查文件系统元数据。
- 只读汇总查到物料图片节点的 `modifytime` 为空；登记节点时保留主键、路径、文件类型及存储标识，不把空时间视为已验证的底层存储版本。
- 元数据中 `bd_material` 与财务、采购、销售、库存、计划、生产、成本、计量和税类存在聚合关系；销售、库存、计划、成本及利润中心成本域有已识别子表。源码的未知关系守卫仍须以 NC 运行时元数据实际验证。
- 现有集团正式动作的 `node_code` 与 `button_code` 均为空。候选升级脚本会备份原节点编码并登记真实节点；回退恢复原值。若旧版已留有不含节点编码的非空备份，升级会停止，须先人工核对原配置。

`06_inspect_task_readonly.sql` 是按集团及请求号限定的数据库管理员排查脚本，不替代按实际组织授权的用户日志界面。
