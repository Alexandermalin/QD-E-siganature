# 物料业务单元新增保存试点

试点覆盖 **物料-业务单元 → 新增 → 保存**，对应 `10140MAO / Save / INSERT`。使用新版签名、策略和审计服务。范围目录仍以 `QD-ES-A7FBCA61C6991D48` 标识。

## 装入候选补丁

1. 使用目标 HOME 的 IBM JDK 7 执行 `tools/build.ps1 -Test` 和 `tools/package.ps1 -SkipBuild`。试点类随现有项目 JAR 发布。
2. 在隔离测试实例或获准的共享环境维护窗口按 [环境实施记录](ENVIRONMENT_EXECUTION.md#操作顺序) 生成部署清单、备份和安装补丁。核对目标数据源为齐都测试库 `QDNC`，并保留功能注册的原参数值。
3. 在 NC「功能注册」中打开 `10140MAO` 的参数，将 `BeanConfigFilePath` 从 `nc/ui/bd/material/config/Material_Config_Org.xml` 改为 `nc/ui/uapbd/qd/esign/QdMaterialOrgConfig.xml`。IDEA 中的源文件位于 `uapbd/src/client/nc/ui/uapbd/qd/esign/QdMaterialOrgConfig.xml`，随新版客户端 JAR 发布。它导入原生物料配置，并替换 `service` 和 `saveAction` 两个 bean。重新登录客户端，确认打开的是物料-业务单元页面。
4. 保持新版策略关闭，使用隔离测试业务单元做一次普通新增保存基线。确认原生 `insertMaterialWithExtendVO` 只调用一次，返回真实物料编码，页面正常刷新。保留打开节点、实际 `saveAction`、物料所属业务单元及原生 RPC 的核对结果。

建议用 `990 测试业务单元1`（`0001A9100000003UDS6R`，集团 `0001A9100000000005MH`）。现场已核对 `yonyou02` 的角色关联到该业务单元及 `10140MAO`，联调时要显式选中 `990` 并确认实际授权。账号默认业务单元 `0001A910000000001O7X` 会通过 `BD_MATERIAL_TRG` 写入 WMS 队列，启用脚本会拒绝该业务单元。试点前仍需确认共享环境维护窗口、外发任务隔离，以及页面和服务端实际使用的 `pk_org`。

## 通过策略页启用 990

1. 完成 [组织策略 1.1.0 升级](ORGANIZATION_POLICY.md) 后，记录 `990` 的总控及物料试点行状态，核对原生新增保存和外发隔离。保持组织总控关闭。
2. 在具备事务能力的 Oracle 测试会话中关闭自动提交，按 `990` 的集团和业务单元主键绑定 `:pilot_group`、`:pilot_org`，绑定 `:pilot_enabled=M` 执行 `sql/nc65-electronic-signature/material-save-pilot/configure.sql`。确认回显为 `10140MAO / Save / INSERT`、`PILOT / Y`，且总控和按钮策略回显与执行前一致后提交。既有 `Y` 模式用于直接启用全部试点开关。
3. 在 NC「职责-集团」建临时职责 `QD_ES_MAINT_990`，分配 `QD_ES_POLICY` 节点与 `QUERY`、`SAVE`、`MASTER` 三项业务活动。在「业务类角色」建同名角色，关联该职责并把授权组织限定为 `990`。在「用户权限分配」仅分配给 `yonyou02`。用「用户功能权限查询」确认角色范围和三项权限，保留已有日志查询权限。
4. 以 `yonyou02` 重新登录后，在策略页选 `990` 并查询。先勾选试点行的签名、事由必填和审计，点「保存策略」并重新查询验证。再单独开启并保存组织总控。按同一请求号核对签名和审计页。

新增保存调用原生扩展保存接口。其完成后，试点在同一服务端事务中读取已持久化的物料主档字段，写入审计、字段差异和 AFTER 快照。该接法无需新增平台事件监听器。普通更新、复制新增、版本新增和「保存新增」继续使用原动作路径。现场原生业务单元配置的自定义扩展服务上下文为空，标准物料数据随原 `MaterialVO` 保存。遇到未经核验的自定义扩展服务映射时，受控调用会中止。

## 验证与撤回

用同一测试账号和业务单元测试，每个用例使用可辨识的物料样本。绑定 `:pilot_org`、`:pilot_user_code` 运行 `sql/nc65-electronic-signature/material-save-pilot/verify.sql`，按请求号关联签名、业务对象和审计。

| 操作 | 通过标准 |
|---|---|
| 事由必填时留空确认 | 弹窗提示输入事由，业务保存未发生。 |
| 新增保存后取消签名 | 签名日志记录 `CANCELLED`。物料未保存，审计和 AFTER 快照均无记录。 |
| 新增保存并正确签名 | 弹窗一次，原生新增调用一次。真实物料主键和编码被回填，签名、业务均为 `SUCCESS`。同一请求和对象有一条签名、一条业务审计及一条主档 AFTER 快照。 |
| 仅签名、仅审计、两项都关闭 | 仅签名时弹窗且只生成签名日志。仅审计时直接保存并生成业务审计。两项都关闭时走原生保存。 |
| 签名成功后原生校验拒绝保存 | 保留成功签名，业务为 `FAILED`，原生物料和业务审计均无新增。 |
| 在专用隔离环境注入审计写入失败 | 业务新增与审计一并回滚，独立签名仍可查到。 |
| 修改保存、复制新增、保存新增，以及其他业务单元的普通保存 | 执行原生路径，试点范围内无额外请求。 |

联调结束先在页面按试点前记录恢复行开关和组织总控，重新查询确认后撤回 `yonyou02` 的临时角色。需要退出试点接入时，绑定 `:pilot_enabled=N` 运行同一脚本，检查试点策略已停用后提交，再恢复原 `BeanConfigFilePath`，按补丁备份撤回并重新登录。保留请求和日志用于核对。
