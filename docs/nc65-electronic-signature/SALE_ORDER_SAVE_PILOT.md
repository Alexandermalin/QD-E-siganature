# 销售订单新增保存电子签名试点

本批候选范围是 990 组织的 `40060301 / Save / INSERT`：在销售订单维护页手工新建一张普通订单后保存。客户端、服务端和策略维护都限定该组织；其他已知组织沿用原生保存。复制、参照生成、修改、批量、收款抵消和其他复合业务不在本次试点中。`保存并提交`使用同一个保存动作；只有保存部分属于本试点，提交动作尚未接入。

截至 2026-11-10 的 QDNC 只读检查：`990 测试业务单元1`（`0001A9100000003UDS6R`）同时是启用的业务单元和销售组织；`yonyou02` 的 `full01` 角色关联了该组织和销售订单节点。原生按钮权限仍需在 NC 会话中确认。990 的组织总控已经开启，已有物料保存策略启用；本试点脚本不会修改总控或其他策略。销售保存映射目前仍为 `UNMAPPED / N`，无销售保存策略。

## 接入方式和限制

客户端保留 `SaleOrderSaveAction`，按原始流程收集订单、流程用户对象及预分配主键。受控保存进入销售专用网关，在业务事务内调用 NC `IplatFormEntry.processAction` 的 `WRITE`，而不是直接调用低层订单新增接口。网关只接收一张新订单，并核对集团、销售组织、交易类型、预分配主键、PF 参数与原生返回值。审计开启时读取实际落库的订单表头和表体。

现有 NC65 的 `PfUtilClient` 没有公开的最终调用替换点。候选接入对该类的字节码 SHA-256 做固定版本校验，并通过该版本原生的客户端前置方法执行提示及保存审批流检查；类版本不符或存在不支持的扩展参数、复合动作、额外校验器时拒绝受控保存。此做法依赖现场 NC 客户端版本，必须通过真实窗口联调，不能把离线测试当作流程兼容或事务回滚证明。

现场仍登记了 `PluginBeanConfigFilePath=nc/ui/so/qd/esign/config/saleorder_esign_probe.xml`，旧 probe 属性有 `saveMode=DENY`。在已配置的本机依赖 JAR 和对应的客户端 classes 中未找到该 XML；尚不能据此证明远程客户端缓存或其他加载路径没有生效。必须现场核对实际保存动作类及拦截器链，确认旧版 probe 不拦截或与本试点兼容。不要覆盖或删除旧版配置来排障。

## 部署与启用

1. 在共享测试环境的维护窗口确认用户及后台外发任务影响、目标数据源和文件备份。先完成 IBM JDK 7 完整构建和候选包校验，按环境实施记录安装项目补丁；不要覆盖 NC 产品 JAR。
2. 保存 `40060301` 的原始功能参数。将 `BeanConfigFilePath` 从 `nc/ui/so/m30/billui/model/saleorder_config.xml` 改为 `nc/ui/uapbd/qd/esign/QdSaleOrderConfig.xml`，保留已有 plugin 参数。重新登录或刷新客户端后，核对实际保存动作是 `QdSaleOrderSaveAction`，并检查完整旧拦截链。
3. 保持销售保存策略关闭，在目标客户端重复一次 990 单笔普通新增保存，确认页面正常、真实订单号返回，且原生 PF 保存仅调用一次。确认该交易类型、客户端前置流程和额外参数均属于上述支持范围。
4. 在支持事务的 QDNC 会话关闭自动提交，绑定 `:pilot_group=0001A9100000000005MH`、`:pilot_org=0001A9100000003UDS6R` 和 `:pilot_mode=REGISTER`，执行 [试点映射脚本](../../sql/nc65-electronic-signature/sale-order-save-pilot/configure.sql)。脚本会核对版本、组织、节点参数、按钮和既有策略，不会自行提交。检查回显后提交。
5. 以具备策略维护权限的账号在业务单元策略页选择 990，仅配置销售订单保存的签名、事由和审计开关。990 总控原本已开启，应保留其他策略和总控状态。以 `yonyou02` 重新登录后确认销售保存及日志查询权限。

只有在 990 被证明不适用时才考虑用户提出的扩大组织范围；逐组织核对实际销售权限、既有总控与外发影响，并修改代码后重新构建和验证。当前代码及映射脚本固定 990，不会自动为其他组织创建策略或打开总控。

## 验收与撤回

每个用例使用可辨识的新测试单，记录账号、销售组织、订单号、请求号、签名结果和审计编号。使用 [只读核对脚本](../../sql/nc65-electronic-signature/sale-order-save-pilot/verify.sql) 按请求号核对。

| 用例 | 预期 |
|---|---|
| 必填事由留空、取消签名 | 不保存订单；取消签名有取消记录，业务审计不应新增。 |
| 正确签名并保存 | 仅弹一次签名；原生 PF 保存一次；签名、业务均成功；真实订单号回填，同请求关联订单头和实际表体的 AFTER 快照。 |
| 仅签名、仅审计、两项均关闭 | 分别验证弹窗及日志组合；关闭时沿用原生保存。 |
| 签名后原生业务校验失败 | 成功签名保留；订单和成功业务审计均不落库，业务记录失败。 |
| 审计写入故障 | 在隔离条件下注入故障，核对订单与审计共同回滚，独立签名仍可查询。 |
| 复制、参照、修改和保存并提交 | 确认各自的原生行为与试点范围，保存并提交的提交部分尚未纳入签名。 |

结束时先恢复销售保存的策略开关并排空执行中请求；绑定 `:pilot_mode=DISABLE` 执行同一脚本，检查映射已停用并提交。按备份恢复原 `BeanConfigFilePath` 和项目补丁，保留测试请求和审计证据。不要关闭原有物料策略或整体恢复共享数据库。
