## 验证与边界

- NC Home 自带 JDK 的隔离编译和离线套件通过，完整隔离编译基线记录于 `build/base-archives-check/fresh-full-20261111-0327-compile.log` 和 `build/base-archives-check/fresh-full-20261111-0327-tests.log`；该编译不依赖本项目旧编译目录或已部署项目补丁，后续变更仍须重新编译。批量删除调度测试覆盖成功、标记回滚、结果未知、未执行及结果写入失败；生产及树形分类级联测试覆盖影响行、不同所属组织、范围变更和非法载荷；冻结和启停候选测试覆盖批量载荷、所属组织策略、逐对象结果、关联行和异步日志变化、归档证据及客户端配置；银行候选覆盖共用账户、各档案正式动作与策略版本、账户关系增删、账户主行、币种及使用组织行、双人启用校验及候选弹窗配置；主档和批改候选覆盖结构范围变化、跨类型策略、字段及值变化、原生校验阶段的对象排除证据、部分成功和未变化结果。离线测试使用替身或静态配置，不证明 NC 会话、原生权限、异步回调或 Oracle 事务行为。
- 本轮直接只读核查了客户、供应商页签、对应原生按钮与主子表字段；分类供应商根节点使用 `parent_id='~'` 的样本已观察。物料生产服务在所选行的 `classfeature` 为真时，会修改同组织、同成本类的其他生产信息行；候选适配对每个影响对象分别解析策略和采集快照，签名窗口列出全部影响物料。2026-11-11 间隔重试 QDNC 仍连接超时，货位与仓库的组织关系等数据尚未核实。
- 离线核对原生实现发现：客户、供应商主档启停也会同步 `bd_cust_supplier` 的状态；启用还会处理异步删除日志。仓库保存涉及 `bd_stordoc` 及 `bd_agentstore` 子行。主档适配必须把这些变化和真实事务边界纳入，而不能只采集主表。
- 客户和供应商启停候选沿用原生一次批量提交，主档及 `bd_cust_supplier` 以各自主键对齐，`bd_ansylog` 按 `pk_basdoc` 记录；若原生报告失败或未变化的对象却发生关联行或日志变化，候选使该次受控事务回滚。现场仍需核对 NC 的元数据权限、业务锁及事务传播，不应据此登记为已验收。
- 客户、供应商主档普通保存尚未接入：原生新增可能自动分配至所属组织并建立客户与供应商关联；修改会同步共用主档及关联的另一类档案。主档上级变化还会通过结构服务增删或更新结构行及内部编码。必须按实际关联档案的所属组织和对应正式动作逐项判断策略，并扩展结构影响范围，不能仅记录所选主表行。
- 主档修改范围候选根据原生结构内部编码的无集团过滤前缀读取下级，并核对同主键关联档案、旧上级、新上级和所属组织；另一类档案是否存在由服务端查询，不由客户端决定。其请求固化范围摘要并在后续阶段复核，快照候选覆盖主档、客户供应商关联行和结构行。原生保存同时使用动态扩展服务，且关联同税号客户或供应商时可能走不同服务；扩展的服务登记、物理表、事务与原生关联确认尚未核实，因此没有接入业务适配器或按钮，也未启用该动作。
- 原生快速批改会过滤未变化行，并可能仅返回成功对象和汇总错误；错误文本没有可靠主键。客户、供应商主档候选服务跟踪原生权限、业务校验和事件阶段实际排除的对象，结果核对仅接受明确返回的成功、服务端确认未变化和具有排除证据的失败；结果无法归属或未确认成功对象发生变化时拒绝提交。候选摘要绑定集团、操作组织、全部所选主档及选中和联动字段、类型和值；签名窗口显示对象及完整值，时间和数值按完整精度区分。服务端读取原生批改配置，核对服务、字段和物理元数据，原生客户端弹窗候选通过一次签名接至受控事务。当前仅处理客户、供应商主档页签，明确拒绝配置了自定义校验器的字段、所属组织、结构编码、扩展表及其他未核实字段；组织页签和物料批改尚未实现。客户端和服务端源码均未登记、部署或现场验证。原生监听器、关联表、配置并发变化、业务锁重入和独立事务的行为仍需在 QDNC 验证，不能将候选当作已接入或已验收。
