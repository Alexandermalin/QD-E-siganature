# 技术设计与实施契约

版本：开发基线 2026-11-07。下文描述目标契约；代码是否已交付必须同时核对任务台账和测试报告。

## 核心接口与数据流

- `nc.vo.uapbd.qd.esign`：`OperationContext` 包含请求/批次、会话用户、集团/业务单元、节点、按钮、操作类型、对象、事由以及签名/业务状态；`BusinessObjectRef` 保留对象类型、临时标识、真实主键/编码和父子关系。
- `SignatureRequest`/`SignatureResult` 分离身份确认和业务执行结果。密码只在当前认证调用中使用，不进入上下文、持久化 VO、调试输出、错误堆栈描述或 CSV。
- `PolicyDecision` 分别表示签名、事由必填、审计和总控决策；新策略默认关闭，全部业务单元可配置。
- `nc.itf.uapbd.qd.esign.ISignatureService`、`IPolicyService`、`IOperationService` 提供签名、策略和操作请求服务。方法以实际 Java 契约为准，不能绕过服务端身份与组织校验。
- `nc.bs.uapbd.qd.esign` 下 core/adapter/audit/security 分担状态、平台桥接、对象快照与差异、安全处理；`nc.impl.uapbd.qd.esign` 暴露服务实现；客户端位于 `nc.ui.uapbd.qd.esign`。

## 状态与幂等

身份确认结果与业务结果是两个字段/状态轴。认证成功不推导业务成功；业务状态至少能够区分未执行、执行中、已提交、失败/回滚和待核对。取消与认证失败不得调用业务服务。

请求编号由服务端生成并绑定当前会话用户、组织、操作、对象集与策略决策。重复使用、跨用户/组织使用、对象篡改和超时应拒绝。一次批次的认证结果展开为每对象签名日志；日志用稳定业务键及数据库唯一约束防重。客户端防重只解决交互重复，服务端持久化幂等才是最终边界。

节点注册显式包含允许的operation_types及object_type，prepare和执行均以权威映射校验上下文，不能以SAVE按钮授权调用DELETE。请求独立保存policy_version与control_version，总控关闭再打开不能恢复旧授权。

授权认领先于原业务CMT独立提交：外层IOperationService(tx=NONE)调用local IOperationTransactionService.claim(CMT)，生成并保存不回传UI的execution_token和RUNNING状态，再调用executeClaimed(CMT)执行业务及审计。失败由独立finishFailure(CMT)保存；状态写入也失败时保留RUNNING防重、显式报告，不释放READY。禁止把claim与可能回滚的原业务放同一CMT。

业务动作因原校验失败后，结束当前授权；用户修改后再次点击必须产生新请求并重新认证。客户端断开、原拦截器返回 false、外部成功后本地失败等不明确结果不得自动推定成功，应通过请求状态、故障记录与人工核对处理。

## 策略、窗口与权限

按业务单元总控及同组织的节点和按钮配置解析策略。真实 NC 编码未辨认的清单行只读。签名准备、密码确认和业务执行从实际业务单元读取策略及版本。

签名窗口使用 NC 原生 UIDialog/UIPanel/UILabel/密码输入与事由输入组件，展示当前登录人员、功能、动作和对象摘要；关闭窗口与取消按钮均记录一次取消事件并终止业务。服务端不能接受窗口指定另一个用户。

策略管理、签名查询、审计查询、导出、归档状态及异常查询分别绑定 NC 原权限；服务端同时校验组织范围和功能权限，不能只靠客户端隐藏按钮。平台权限注册脚本先核验环境，不直接猜测产品权限表并写入。

权限实现使用真实FunctionPermProfileImpl公开subject信息及原生FuncSubInfo。必须在同一subject中同时满足按钮与BU，不能将角色A按钮和角色B组织并集拼接。原业务按钮沿用isValidButton对未注册按钮的原生语义；新管理/日志按钮严格要求REGISTERD_HASPERMISSION。不能使用本机恒返回null的getButtonPermissionOrgs。实际RBAC服务调用、组织类型过滤及业务活动组合仍需NC验证。

## 审计与字段差异

旧快照必须在真实写入/删除前读取完整聚合对象，包含表头、表体、货位/单品/关联明细；使用稳定行主键及父键比较，不按屏幕行号配对。按节点业务字段白名单采集；认证字段、密钥、令牌、密码及其摘要均排除。

修改比较应规范化数值、日期、布尔、空值和参照值，保留字段标识/名称、原值/新值和行关系。无实际变化可记录保存行为但差异为零。审批/签字等状态动作仍以真实提交数据比较，不能只记录按钮名称。

审计失败按已批准规则中止/回滚同事务业务；独立签名日志保留。禁止吞异常。尚不能证明同事务写入的节点保持禁用并记录阻塞。

## 查询、导出与归档

在线及历史查询必须带授权组织集合，按日期定位月份目录，再统一过滤、排序和分页；请求关联需跨月定位。CSV 使用 UTF-8 BOM、RFC4180 引号和换行处理，并中和可执行公式前缀；限制导出规模，分批读取且复用服务端过滤与权限。

每月 1 日凌晨按 Asia/Shanghai 计算截止月，保留当月及前两个月；按月搬移签名、审计、对象、差异、快照及安全事件。归档任务使用目录/作业状态、校验计数和可重入防重；只有复制并校验成功才移除对应在线数据。月表由确认后的部署 SQL 预建，运行任务不自行执行 DDL。归档失败明确记故障并可安全重跑，历史统一查询必须在验收中验证。
