# 出库申请单离线候选交付说明

**受控单张审批暂不可启用：**本机 NC 普通审批窗口的加签动作会在窗口返回前调用工作流调整服务，附件也可能在窗口返回前上传；当前候选是在窗口返回后验签和派发审计。这些操作可能先于电子签名和业务审计发生，现有测试未覆盖该路径。需修正确认与事务边界并完成现场验证后，才能启用相关受控审批；不能依赖用户不点击相关功能来视作已修复。

候选已按原生流程处理加签或指定审批人结果：不再把其继续派发为审批，也不生成审批签名或审批审计。这不等于加签／指定审批人已接入电子签名，且不能撤销窗口中已经发生的动作。

**交付状态：离线测试通过，现场联调待完成。** 此状态仅适用于包内 `evidence/build-result.json` 标明 `tests_passed=true` 且包清单校验通过的构建，不代表 NC 功能验收或允许启用。

范围为节点 `40080801` 的八项单张候选、保存并提交，以及普通删除、提交、收回、审批和取消审批的受控批量候选。多单一次验密、部分成功和本机标准库存批量回调已接入候选流程；实际 NC 回调、锁及事务尚未验证，受控批量不能据离线测试认定为现场可用。行操作预算提示续做及部分复杂审批参数待开发。现场按钮、数据权限、插件、事务传播与回滚待验证。盘点及库存调整 25 项暂停。

保存并提交沿用 NC 的先保存、再提交顺序。两个步骤分别按 `Save` 和 `Commit` 策略执行。保存成功并返回单据后，提交前核对集团、组织和真实主键。提交取消或失败时，已完成的保存仍然有效。两个步骤均启用签名时分别验密。

受控审批尚不支持旁批参数；策略关闭时保留原生路径。批量审批在原生确认后按整批一次验密，绑定审批意见、流转选择、单据和当前用户，再由 NC 生成逐单工作项。审批任务、共享／委托审批及其现场事务仍需核实。

QDNC 基础类型 `4455` 注册了两个预算客户端流程扩展。现场需核对相关流程参数、扩展实际调用及其事务；不能仅凭注册记录认定扩展一定触发，也不能将其等同于行操作预算续做。

对已核对版本的库存标准回调，批量审批候选按原生规则合并服务端原单和已签客户端单据并恢复货位，再核对逐单结果；进入原生业务前再次检查签名输入、原单、审批意见和参数。离线模拟通过，真实客户端单据及现场回调仍需验证。

批量取消审批没有原始确认说明时，候选仅接受空值或 NC 新建的空逐单说明；其他逐单说明会拒绝，需在现场核对交易类型和工作流配置。

原生批次返回逐单异常时，即使异常文字为空也会显示提示；缺少已提交回执的单据仍需按请求号核对，不把异常等同于已回滚。批量部分成功的轻量单据按主键对齐后刷新，异常主键需重新查询；现场仍需用真实单据验证。

受控库存业务在提交前要求 NC 原生事务只涉及一个已登记数据源；无法确认时标记业务事务回滚。该保护已用 NC 事务类替身离线测试，不能代替现场回滚验证。

## 交付内容

- `sources/`：与构建记录逐个核对 SHA-256 的 Java 源码、离线测试源码及客户端 XML。
- `modules/`：全项目隔离构建生成的附加 JAR 和 `qd_esign*.upm`，其中共享 JAR 也包含其他业务代码；安装前须与现场现有版本及依赖比对，不得直接覆盖整个目录或 NC 原产品 JAR。
- `config/`、`sql/` 和 `docs/`：范围矩阵、配置、只读预检与安装资料；候选策略和映射默认未启用。
- `release-manifest.json`、`evidence/build-result.json`：文件及 JAR 条目摘要、构建环境和测试记录。

## 测试环境安装

1. 核对包清单和 JAR 摘要，备份测试环境已有附加 JAR、UPM、配置及插件顺序；比较共享组件差异，确认与现场现有版本和依赖兼容后，仅选择本次所需组件按 NC65 现场流程安装并加载。包内还包含其他业务模块，不要整包覆盖安装。
2. 审核基础表及版本状态，按实际安装情况选择 SQL；不得重复执行已安装的建表脚本。先运行 `sql/nc65-electronic-signature/inventory-pilot/sapply-preflight.sql` 的适用只读部分，核对动态表、交易类型、组织、按钮和插件。将 `:pilot_bill_type` 填为试点单据的实际交易类型编码，检查基础类型和试点类型的审批动作；再核对服务端实际加载的工作流配置。
   出库申请的八条候选映射可按 `sql/nc65-electronic-signature/sapply-pilot/README.md` 审核和暂存；脚本不注册 BP 规则、不启用策略，且所有映射保持未验证。映射全组织共享，运行前须核对全部相关策略、备份原行并按说明安排测试维护窗口。
   预检中的 `LEGACY_NUMBER4` 表示请求对象计数字段仍为旧版 `NUMBER(4)`：本候选的 1000 对象上限在其范围内，但当前升级脚本期望 `NUMBER(6)`；大于 9999 对象的其他批处理须先按升级说明核实。预检不会修改字段。
3. 备份节点 `40080801` 原客户端配置与插件顺序；候选配置路径为 `nc/ui/uapbd/qd/esign/QdSapplyConfig.xml`，对应客户端 JAR 中的同名 Java 配置类。本机 NC65 的 UIF2 工厂可按该路径加载该类，但现场版本及插件兼容性须实测。按 [库存接入说明](INVENTORY_INTEGRATION_20261111.md) 核对九个 BP 的前后规则与顺序；`sapply-rule-preflight.sql` 可只读检查 18 条规则登记是否缺失或重复，结果不证明规则已经加载或与业务同事务。`sapply-pilot/02_stage_bp_rules.sql` 提供需现场审核和 NC 主键的登记候选；本包不会自动执行 SQL 或启用策略。
4. 受控批量的候选 `.upm` 和 `.aop` 位于 `examples/uapbd/config/examples/sapply-batch/`。候选切面分别绑定原生 PF 批量入口和逐单工作流入口。候选仅允许与本机字节码一致的库存标准回调或无回调配置，其他回调及不同版本会停止；QDNC 的交易类型记录配置了库存标准回调，但现场实际加载版本、原单参数、锁及事务仍需验证。不要仅凭数据库配置或离线替身测试启用受控批量。

## 验证

使用具备授权的测试用户和业务单元，逐项验证四种签名／审计开关、取消、错密、越权、重复提交和审计写入失败回滚。核对单号、请求号、单据及动态行、审计快照和库存记录。行关闭／打开同时核对未选行状态及 `IC_SAPPLY_E` 动态字段是否保留；可用受控测试数据验证未选行空状态保持不变，选中行空状态须拒绝。单据只读核对 SQL 的短 `CHAR(20)` 主键适配待现场核对。

受控行操作已派发后如出现业务异常、通信异常或无法核实的返回结果，按提示中的请求号先核对单据及审计，不要凭客户端异常推断提交或回滚；已返回结果但界面刷新失败时也需按请求号重新查询。嵌套的预算提示会尽量显示原生预算原因，不自动续做。`sql/nc65-electronic-signature/inventory-pilot/verify-sapply-request.sql` 提供授权行当前状态及审计差异的只读查询，但当前状态不能单独证明先前事务结果。预算提示的续做尚未接入。

现场预检脚本还列出行关闭／打开相关事件、监听器及出库申请表触发器；请核对事件来源、各进程实际加载情况及关联系统，再通过注入失败验证业务回滚。

在隔离测试环境核对实际后台调用：NC 上下文集团和数据源有效、策略关闭时，未带交互用户档案的调用应按原生权限与规则执行；对应策略开启时未经授权的 BP 调用须被阻断。缺少集团／数据源或读取策略失败时应拒绝，不能据离线测试推断所有自动任务均兼容。

保存并提交需测试手工新增及修改、两步策略分别开关、保存取消后停止、保存后提交取消或失败、刷新和切换选择，以及按同一单据主键核对两步审计。

普通受控批量对同一组织、同一交易类型的选中单据创建一次授权，并将通过原生预校验的单据作为一次 PF 批次提交，保留 NC 服务端逐单事务。需要签名时整批验密一次；普通动作的签名发生在原生预校验前。未通过预校验的单据标记为未提交，不采集业务审计；全部未通过时停止。现场以三张单据验证中间单审计失败、首尾两单提交及独立签名保留。另测一张及多张预校验失败、只剩一张可提交、权限拒绝、取消、重复请求、批次异常及客户端刷新，按真实单号和请求号核对成功、未提交及待核对的回执。现场需验证批量收回和删除的服务端单据权限与客户端配置一致。

批量审批和取消审批在原生预校验及审批确认后签名；签名绑定完整选择、通过预校验的提交范围、审批意见和流转选择。还需在现场核对审批弹窗显示、当前用户、逐单工作项与流转选择，以及中间单失败时其余单据的事务和回执。

仅在原生逐单动作开始前被拒绝的单据可标为失败；进入原生动作后若缺少已提交回执，结果标为待核对。原生异常或事务回滚标记本身不能证明业务已经回滚。

## 回退

先关闭对应测试策略，核对未完成请求及单据和库存。恢复安装前的节点配置、插件和规则顺序，按备份撤回本次附加 JAR、UPM 和已装载的批量切面。保留签名及审计记录。本机规则加载器读取 `PUB_PLUGINITEM` 时未在该查询中按 `DR` 过滤；仅设置逻辑删除标记不能证明规则已撤回，须按现场 NC 的规则管理流程撤销登记，并核对各服务进程实际加载状态。
