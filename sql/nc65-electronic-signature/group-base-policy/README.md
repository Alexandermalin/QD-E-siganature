# 基础档案集团策略升级

该升级以正式范围清单的 77 项基础数据操作为集团策略目录。集团按钮配置按集团和正式操作标识保存。业务单元策略继续配置其他操作。原 `qd_es_control` 仍供 1.0.0 迁移及撤回使用。

## QDNC 测试库

1. 运行 `01_precheck.sql`，确认目标为 QDNC 测试环境、已应用 `1.1.0`，并保存现有基础档案业务单元配置和运行映射。处理所有 `RUNNING` 请求后停 NC 中间件、客户端和归档任务。
2. 运行 `02_create_group_policy.sql`。Oracle 建表及修改表结构会隐式提交。若中断，按预检结果核对已经创建的对象和约束，再执行剩余语句。
3. 关闭自动提交，运行 `03_migrate_group_policy.sql`。核对 77 个正式操作均已分类，集团总控全部关闭且版本已推进，再提交。原有业务单元基础档案策略保留备查。集团配置从关闭状态开始。
4. 安装同一构建的接口、服务端和客户端文件，并按现场注册脚本登记集团策略节点 `QD_ES_BD_POLICY`。对当前集团角色分别授权 `QUERY`、`SAVE`、`MASTER`。用授权角色和普通业务单元角色验证原生权限档案与集团边界。
5. 每个正式范围标识可以关联多个经验证的实际按钮。新增映射使用不同的 `scope_id` 并通过 `group_scope_id` 指向正式行。只有已验证的真实按钮可以执行受控操作。现场启用前核对目录、运行映射、实际保存链路和事务证据。

## 软件撤回至 1.1.0

在维护窗口停服务并排空 `RUNNING` 后，关闭自动提交运行 `04_prepare_rollback.sql`。核对集团总控关闭、集团节点别名解除验证以及原业务单元基础档案策略已停用，再提交并从同一备份恢复 1.1.0 的客户端、服务端和节点配置。保留新增结构、原策略配置值和审计历史。启用旧基础档案策略前先按撤回前备份逐项核对。
