# QDNC 电子签名管理菜单注册

本次交付供审阅。注册目标是齐都测试库 QDNC 的 `defaultMenu → 企业建模平台 → 电子签名管理（新版）`。使用开发环境中已部署的 `qd_esign_uapbd_client.jar`。

## 注册与授权范围

| 菜单编码 | 功能编码 | 功能名称 | 注册按钮 |
|---|---|---|---|
| `109801` | `QD_ES_POLICY` | 电子签名策略 | `QUERY`、`SAVE`、`MASTER` |
| `109802` | `QD_ES_SIGNLOG` | 电子签名日志 | `QUERY`、`EXPORT` |
| `109803` | `QD_ES_AUDITLOG` | 业务审计日志 | `QUERY`、`EXPORT` |
| `109804` | `QD_ES_SECURITY` | 登录与安全事件日志 | `QUERY`、`EXPORT`、`GROUP_SECURITY` |

四条功能采用普通功能、模块 `1014`、业务单元类型和各自的客户端类名。功能注册分类编码为 `QD_ES_MGMT`，默认菜单父项编码为 `1098`，上级为 `10`。注册明细包含功能、按钮、业务活动和试点集团的按钮权限控制。

试点职责和角色都用编码 `QD_ES_QUERY_990`。职责含四条功能权限和四条 `QUERY` 活动权限。该角色归入现有业务类角色组 `990`，分配给普通用户 `yonyou02`，角色的授权组织为 `990 测试业务单元1`。预计在 12 张 NC 表中新增 57 行。

## 脚本与核对顺序

1. 在「齐都药业测试库」连接选择 QDNC，执行只读预检，要求 23 项均为 `OK`。预检涵盖数据库与会话标识、菜单位置、角色组、普通用户、业务单元、集团总控和全部预留对象。 [预检 SQL](01_precheck.sql)
2. 审阅并确认本批脚本后，在测试维护窗口执行完整注册文件。使用同一个可回滚事务，出错即停。采用 DBX 批执行时设置 `database=QDNC`、`use_transaction=true` 和 `continue_on_error=false`。脚本用 `NOWAIT` 锁定功能注册、菜单项、职责和角色四张配置表。首条写入重查预检条件，末条写入在核对前 56 行和授权关系后才分配试点角色。检查失败会触发主键非空错误并使事务失败。 [注册与授权 SQL](02_register.sql)
3. 执行三条核对查询。预期为 12 张表的计数均匹配、10 条按钮明细均为 `OK`、8 条试点授权均为 `OK`，其中功能与查询活动各四条。手动提交的会话在核对成功后提交。DBX 整批执行返回成功后，在独立会话核对持久化结果。 [核对 SQL](03_verify.sql)
4. 执行缓存版本补充检查。预览应返回 11 行，状态为 `REFRESH` 或 `OK`。在手动提交会话更新需要刷新的版本，重查 11 行均为 `OK` 后提交。让实际连接的中间件重载表版本，再完全退出并重开 Java 客户端。用 `yonyou02` 登录，选择 `990` 验证四个菜单、查询与权限边界。 [缓存版本 SQL](05_refresh_cache_versions.sql) · [NC 客户端验证清单](../../../docs/nc65-electronic-signature/MANAGEMENT_MENU_VERIFICATION.md)

提交前需要撤销时，在原会话回滚事务。提交后需要撤回时，先核对已安装状态，再在支持匿名 PL/SQL 和手动提交的 Oracle 会话执行撤回脚本。脚本检查后续关联，按此次写入的主键、编码及所属关系定位待撤回行。核对通过后提交撤回事务并刷新 NC 缓存。 [撤回 SQL](04_rollback.sql)

## 现场依据与验证结果

- QDNC 实测的默认菜单主键为 `1004ZZ10000000000FFL`。试点集团为 `0001A9100000000005MH`，业务单元为 `0001A9100000003UDS6R`，账号主键为 `1001A910000000016OHR`，业务类角色组为 `1001A9100000009E4341`。
- 注册字段和默认值来自 QDNC 元数据。功能及业务活动关系参照 `10180QRYTPL`、`10140SUG`，角色与职责关系参照 `9903`。NC65 的 `RbacSqlUtils.QUERY_PERM_FUNCINFO_SQL` 通过职责的类型 0 条目识别功能，业务活动授权使用类型 2。项目本批使用专用 20 字节主键 `1001A9QDESM…`，以便重入检查与定点撤回。
- 现场预检 23 项通过。现有四个新版节点及菜单均为 0，集团签名总控为关闭。字段、核对查询和撤回依赖检查已在 QDNC 只读验证。
- 用候选行在 Oracle 中做只读预演，10 条按钮路径及 8 条授权通过。候选记录齐备时末条写入能取得用户角色主键，缺记录或把任一查询换成导出时返回空主键并触发写入约束。
- DBX 的普通 SQL 批事务已通过只读探测。独立 SELECT 在其批事务模式下无法作为结果断言，因此注册脚本在实际 INSERT 的非空主键表达式中检查条件。

## 提交后核对

2026-11-09 用户提交后，从独立连接只读复查 QDNC。12 张表共 57 行，10 条按钮明细和 8 条试点授权均为 `OK`。默认菜单的「企业建模平台 → 电子签名管理（新版）」下有四个叶子。试点角色 `QD_ES_QUERY_990` 将四项 `QUERY` 授给 `yonyou02`，组织范围为 `990`。集团签名总控当前为关闭。

同日试点账号重新登录 Java 客户端后菜单仍不可见。原注册脚本遗漏了 NC 的表缓存版本更新。菜单、功能记录于 09:43 写入，`BD_CACHETABVERSION` 中的对应版本停在 11 月 4 日。原生 `FuncRegisterCacheAccessor` 通过 `TableVersionMonitor` 和 `ICacheVersionBS` 检测这两个表的版本。原生 `ServerVersionManager.updateVersion` 推进 `CacheTabVersion` 后还会更新中间件内存，因此数据库更新后须让连接的中间件重载该版本。补充脚本已只读核对 11 条待刷新记录，实际更新和 Java 界面验收待执行。 [缓存版本 SQL](05_refresh_cache_versions.sql)
