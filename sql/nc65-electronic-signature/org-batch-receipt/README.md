# 组织页签批改回执：候选数据库契约

这些脚本尚未在 Oracle 上执行或验收。当前工作区没有与实际 WMS、OA 隔离的 NC65/Oracle 环境；不得在共享环境执行这些脚本或启用组织页签入口。

候选记录将目标组织、签名前固定的页签行、每个授权主档的表头及逐页签结果保存在 `qd_es_batch_page`。`NativeOrgBatchReceiptStore` 提供同事务写入候选，要求在原生业务前完成一次性预检，核对结构版本、回退标记、归档保护、执行令牌与请求范围，并在写入失败时标记当前事务回滚。`NativeOrgBatchReceiptReader` 可在只读候选中合并在线与已登记的历史记录，调用方必须重新校验档案、页签及每个目标组织权限。状态查询和客户端恢复已有候选实现；组织页签的客户端调度及原生业务执行仍未接通，相关代码尚未在 NC 或 Oracle 验证，仅有这些脚本不能让功能上线。

`NativeOrgBatchTargetStore` 同时保存目标集合及服务端准备的实际页签主键、所属档案和目标组织；`W` 表头用于区分明确的空集合与旧请求没有保存选择，`V` 保存逐行选择。签名准备中已有同事务写入分支，但当前前置保护会在创建请求前拒绝组织页签，业务认领也保留拒绝保护。后续结果写入候选要求结果和已准备的每一行一致。旧的 S/U 请求可读，但不能按新格式执行；完整业务执行及回执链完成前不得解除保护。

将来在隔离环境验证时，应先停止所有 NC 和归档服务，运行只读的 `01_precheck.sql`，人工核对 schema、数据库、主机、历史月份和在途请求。`02_schema.sql` 至 `06_prepare_selection_rollback.sql` 均带有拒绝执行的环境占位符，需在核对后分别替换为同一隔离目标。Oracle DDL 会隐式提交，`02_schema.sql` 只能在完成审查后运行；如中途失败，应先核对已创建的表、索引和触发器，再决定是否重跑。版本登记及回退 DML 不自行提交，需检查结果后由操作者决定是否提交。

候选迁移为登记的每个月份准备回执历史表，并设置旧归档保护：在线回执仍存在时，禁止旧归档删除相应主档对象或请求。新归档实现必须先移动并核对回执，再移动对象和请求；当回执与请求跨月时，必须检查所有在线月份，而不是只检查当前归档月份。

`05_mark_selection_version.sql` 登记 `1.3.1-SEL` 能力标记；新写入候选同时要求 `1.3.0`、`1.3.1` 和此标记存在，且没有任何相应回退标记。标记仅表示约定，无法证明所有进程都已升级：登记前必须停止旧进程、排空或核对在途及未知结果，并统一替换所有读写服务，不能混用旧版。`06_prepare_selection_rollback.sql` 先停止新写入并保留证据，之后才允许 `04_prepare_rollback.sql` 登记回执回退。旧版读服务不认识 W/V 和部分成功回执，回退后对新格式请求的历史查询须保留能读取新格式的工具或服务，不能删除记录来适配旧版。脚本不能自动判断所有外部服务已停止或验收通过。

安装候选回执表后，后续生成新月份历史表时应给 `generate_history.py` 指定 `--include-org-batch-receipt`。旧部署未安装回执表时，默认生成逻辑及原有七张历史表保持不变。归档候选遇到在线回执尚未迁走的对象或请求会报告 `blocked_receipts`，并保留该月份为部分完成；后台任务优先处理较新的月份，仍需后续补跑。

离线契约检查可运行 `tests/persistence/check_org_batch_receipt_schema.py`。它只比较脚本和 Java 字段等静态契约，不能证明 Oracle 语法、隐式提交、触发器、并发、归档或回滚行为。
