# 出库申请测试映射候选

`01_stage_routes.sql` 供现场人员审核后在 **QDNC 测试环境**执行。它只整理节点 `40080801` 的八条现有范围记录，不插入记录、不注册 BP 规则、不启用策略，也不把映射标记为已验证。包内其他库存节点不受此脚本处理。

2026-11-14 的只读核对显示八条范围记录存在且尚未映射；出库申请没有组织策略记录或未完成签名请求。数据库版本记录至 `1.3.0`，与源码对照的十张相关签名审计表共 173 个声明字段均存在；这是字段名检查，并非完整的结构和兼容性验收。在线 `QD_ES_REQUEST.OWNER_OBJECT_COUNT` 为 `NUMBER(4)`，当前受控批量客户端候选最多选择 1000 张，未验证如此大批次的现场表现。上述结果均是当时的快照，执行前必须重新运行脚本顶部的只读检查并备份原行。`QD_ES_NODE` 是全组织共享映射，不能只检查一个业务单元。

脚本使用全表锁防止检查和登记期间产生并发变更，因此应在约定的测试维护窗口运行，先停止相关操作并关闭自动提交。执行时将绑定参数 `confirm_qdnc_test` 设为 `QDNC_TEST_ONLY`，并由操作人员独立确认连接的是测试库。连接名、Oracle 的 `DB_NAME` 和当前 schema 不能单独证明这一点。

脚本仅接受正式名称一致的未映射种子或完全一致、仍未验证的候选映射；发现其他映射、已启用策略或未完成请求时回滚到脚本保存点并报错。SQL 客户端需正确读取文件的 UTF-8 中文；名称不符时应先查明原因，不要绕过检查。运行后再次查询八行，与备份核对，再由操作人员自行选择提交或回滚。已提交后需要回退时，先关闭节点策略、核对未完成请求，并依据执行前备份恢复这八行；不得清除签名或审计记录。

映射保持 `validated='N'`，因此受控操作尚不可用。后续须由现场人员按包内安装说明核对客户端绑定、服务、九个 BP 的 18 个前后规则和各服务进程的加载情况，再按测试环境配置流程确认映射与试点策略；不能把数据库登记成功视为事务回滚或现场联调已通过。审批最终确认位置和候选实现的已知限制仍须逐项验证。

字段依据：现场 QDNC 对 `QD_ES_NODE` 的列元数据与当前代码中的节点映射、策略和请求查询；适配器接口来自 `ic/META-INF/qd_esign_inventory_adapter.upm`，scopeId 和按钮来自正式库存接入矩阵。脚本只交付文件，未在 QDNC 执行。

`02_stage_bp_rules.sql` 是九个 BP 的 18 条前后规则登记候选。先按文件头说明暂停相关 NC 服务进程、备份并重跑只读检查，再由现场人员通过 NC 主键服务取得 18 个互不重复的 20 位主键，按脚本中 `add_rule` 顺序组成逗号分隔字符串并绑定 `nc_generated_rule_pks`。不得用未经验证的 Oracle 随机函数代替 NC 主键生成机制；未取得合适主键时不要执行该脚本。

规则类随补丁安装在 `ic` 模块，脚本候选 `VEXTENDMODULE='ic'`；须先核对实际部署路径与模块类加载。本机 NC `RuleCollection` 在目标类为空时把 `addBefore` 插入规则列表开头、把 `addAfter` 追加到末尾；如果 `m4455` 已存在任何规则（包括 `DR` 非零的记录），脚本会停止，必须另行评审顺序，不覆盖现有登记。`localtype/industrytype='~'` 依据当前 QDNC 同类规则，但实际适用集团仍须验证。脚本不设 `validated='Y'`，也不启用策略。

规则登记后按现场 NC 流程加载各服务进程，并检查实际类加载、BP 前后顺序、事务和回滚；数据库行存在不代表生效。回退须先关闭策略并按备份和现场规则管理流程撤销新增规则，核对所有服务进程的加载状态：本机加载器读取登记时未过滤 `DR`，仅设置逻辑删除标记不能证明规则已撤回。两个脚本都不自动提交，也未在 QDNC 执行。
